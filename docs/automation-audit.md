# Cityline 自动化可用性审计

更新日期：2026年10月27日。对象：本项目 v0.1.0 当前源码、公开配置模板和浏览器离线测试。

**当前代码已具备本地 Codex 任务服务、单人登记状态机及可配置浏览器驱动；真实 Cityline 账号注册和本次抽签仍未验收。** 等待页面渲染、独立非建号 OTP 验证、后续资料页与该页新增人工步骤的支持已补上，不能再把这些已解决的缺口列为当前故障。源码、配置标记和离线替身测试仍不能证明真实页面已跑通。

当前用户的接入目标为本地 Codex，无需公开 ChatGPT 服务。GPT Actions 材料可留作可选集成；本报告不把公网入口或自定义 GPT 配置列为当前任务的必需条件。

本轮未控制真实网站，未读取参与者资料、私有 `.env`、私人 `cityline.local.json` 或用户的全局 Codex 配置。MCP 是否已在用户客户端启用、重载并实际调用，以及 GitHub 是否已发布，应以相应部署验证结果单独记录。

## 真实启用前仍需完成的事项

### 1. 核实并配置真实页面、国家区号及短信通道

公开模板仍是 `verified:false`，实际账号、资料页、抽签地址与字段选择器留空。`eventUrl` 保存活动说明地址，不是已核实的报名入口。默认拒绝模板是正确的行为。

需要核实实际是否必须先创建独立账号、各页面的必填资料、区号选项及成功／错误标记。美国 `+1` 是否受理、DuoPlus 是否能收到官方短信，不能由示例表单或配置中的号码格式推出。

代码位置：`config/cityline.example.json`；`src/browser.mjs:26–59`、`120–133`、`345–348`。

### 2. 核实建号动作是否符合当前支持的结构

当前真实驱动支持“只有最终 `accountSubmit` 会创建账号”的结构。发送 OTP、输入 OTP 和可选的独立验证按钮，必须先核实不会建号或接受条款，才能把对应 `*IsNonConsequential` 标记设为 `true`。

这项限制现在已由代码执行，未知语义不会继续操作。**标记为 true 是本地维护者的核实声明，不是程序自动发现或证明。** 若真实页面通过发送／输满／验证 OTP 就创建账号，需要针对该行为调整状态机及当前动作确认，不能仅改配置值来假装满足支持条件。

代码位置：`src/browser.mjs:44–55`、`307–325`、`388–405`。

### 3. 逐项确认正常页面所需的第三方资源

驱动仍阻止所有非 Cityline HTTPS 请求、Service Worker 和 WebSocket。若实际页面依赖第三方 CAPTCHA、认证或 CDN，它们可能无法加载，即使用户准备手动验证也可能没有可操作组件。

应保持顶层导航限制；如真实页面确有必要的外部子资源，需要单独核实并设计明确来源列表。新窗口或第三方认证页面需要专门适配。不要直接允许所有域名来使演示通过。

代码位置：`src/browser.mjs:148–160`。

## 仍需明确的功能边界

- **不自动读取确认邮件或 DuoPlus。** 没有 Gmail／短信服务接口实现。`ballotConfirmationNumber` 虽在模板中，当前驱动未据此提取结果。`awaiting_email` 接受用户提供的编号并标注 `user_reported`；不能表述为“系统已独立核验官方登记成功”。代码：`src/browser.mjs:70–78`、`351–356`、`429–432`。
- **多个 OTP、邮箱验证链接等流程尚未覆盖。** 现在支持一次账号 OTP 与可选独立非建号验证，不能据此推断支持多个 OTP、邮箱链接、所有国家分支或所有登录方式。
- **验证码错误仍需真实错误标记适配。** 字符格式正确不代表官方校验通过。若官方返回错误，应区分可安全重输和结果不明；当前没有可配置的验证码错误处理分支，不应统一自动重试。代码：`src/browser.mjs:388–405`。
- **iframe、新窗口和部分静态资料展示仍需适配。** 当前选择器作用于 `session.page`，没有 frame 路径或切换认证新窗口的实现；后续账号邮箱需要可读取的输入字段，不能直接把静态文本节点当输入框。代码：`src/browser.mjs:159–163`、`195–217`、`235–264`。
- **电话字符串比较严格。** 页面若把同一号码格式化成空格／括号形式，逐字符读回比较仍可能误停。仅在核实页面行为后增加限定标准化，避免放松实际身份检查。代码：`src/browser.mjs:235–264`、`277–305`。
- **真实浏览器中断后不会无缝自动重放。** 任务日志可恢复；除等待邮件等无网页操作阶段，丢失的浏览器会话进入人工恢复，这是防止重复登记的保守处理。代码：`src/browser.mjs:351–356`。

## 验收依据

源码发布、本地 MCP 已配置、客户端实际发现工具、真实页面适配完成、真实登记完成，是不同的可验证结果。对外说明应分别陈述。

本地 Codex 的真实单人流程可用，至少需要：

1. 客户端已重载 MCP，实际能调用工具并查询同一个本机服务的任务。
2. 页面实际顺序符合已支持结构，真实入口、字段、动作语义及结果标记均核实；按需完成剩余适配。
3. 核实该参与者的国家区号与接码能力，并确认必要页面资源正常加载。
4. 通过本地 Codex 工具发起一个真实单人任务，在需要的步骤完成人工验证和当前动作确认，核对实际账号身份与提交结果。
5. 收到官方登记确认邮件；若仅由用户提供编号，继续保留 `user_reported`，不声称独立核验。

**更新结论：通用驱动的等待、多页 OTP、资料页人工步骤和建号语义缺口已明显收敛，相关17项离线测试通过；真实页面、资源依赖、验证码／邮件送达和实际端到端提交仍未由本报告验收。当前仍应以开发预览发布。**
