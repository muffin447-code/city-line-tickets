# Cityline 自动化可用性审计

更新日期：2026年10月28日。对象：当前源码、公开配置模板、离线测试及主任务提供的现场操作记录。本文不包含参与者资料、私有环境文件、私人页面配置或全局 Codex 配置内容。

**结论：本地 Codex 任务服务、模拟流程和通用浏览器驱动已有验证；真实账号由用户手工完成，程序的真实自动注册与抽签完整流程仍未验收。** 页面配置保持 `verified:false`，真实模式未启用。源码、测试通过和人工账号完成是不同证据。

当前部署目标为本地 Codex。GPT Actions 材料作为可选源码保留，本报告不把公网入口或自定义 GPT 配置列为本地任务的必要条件。

## 已实现能力

| 能力 | 当前实现与回归依据 | 可据此得出的结论 |
|---|---|---|
| 本地 Codex 接入 | 自启动 MCP、HTTP 任务接口及真实本机子进程模拟 | 可从已正确连接的 Codex 创建、查询、启动和续跑任务；当前聊天是否已发现工具需单独确认 |
| 单人与重复保护 | 同人任务复用、一次性挑战、进程锁及中断处理 | 正常接口路径不会为恢复而自动重放结果不明的提交 |
| 页面延迟处理 | 有界等待字段可见、可用及阶段标记 | 可处理已配置结构中的正常 SPA 延迟；不自动推断未知字段 |
| 导航开窗与发码分离 | `accountOpenDialog`、`accountOpenDialogIsNonConsequential` 与独立 `accountSendOtp` | 仅核实为无后果的导航开窗可以自动执行，不能把它当作实际发送 OTP 的按钮 |
| 独立非建号 OTP 与后续资料页 | `accountVerifyOtp`、`accountVerified`、`accountDetailsUrl`、`accountInitialEmail` | 支持已经核实的独立非建号验证和后续页面结构，不证明真实 Cityline 的 OTP 后果符合这些条件 |
| 静态邮箱身份核对 | `accountEmailIdentity` 进入账号提交保护，变更后拒绝旧确认 | OTP 页面隐藏初始邮箱输入框时，可用可见静态邮箱文本核对当前参与者；输入框与静态文本同时可见时均需匹配 |
| 分阶段配置 | 账号阶段与抽签阶段分别校验 | 账号准备不要求尚未核实的 `ballotUrl`；不会为准备账号而猜测抽签页面 |
| 等待抽签配置后的安全重试 | 原会话保存账号完成状态及待进入的抽签阶段 | 同一进程、原浏览器会话仍在时，只重试抽签阶段，不重新发送账号 OTP 或重新建号 |
| 密码流程接手 | 用户在本地完成新密码输入、确认、账号提交，驱动观察成功及同人身份标记 | 程序不接收密码，也不在用户只输入密码后代点最终账号提交 |
| 当前提交确认 | 提交前复核 URL、按钮及参与者身份／资料 | 旧确认不能提交已经变化的页面或资料 |
| 完成证据 | 用户提供邮件编号时保留 `evidence.source=user_reported` | 记录用户提供的结果，不等于程序独立读取或验证官方邮件 |

上述浏览器行为通过离线 Playwright 页面替身回归，不是对真实 Cityline 页面、邮箱或短信通道的端到端验收。全套测试命令与部署验证范围见 [验证记录](validation.md)，测试总数以对应运行摘要为准。

## 真实启用前的剩余工作

### 实际账号动作语义

当前通用 OTP 路径只接受“最终 `accountSubmit` 才创建账号”的已核实结构。发送、填写和可选独立验证 OTP 的动作，都必须先确认不会创建账号或接受条款，才能启用对应 `*IsNonConsequential` 标记。

现场出现“OTP 登录或直接开户”的提示，进一步说明不能把这些动作默认当作无后果。维护者将标记设为 true 只是核实声明，不能替代真实行为证据。当前真实 OTP DOM 与后果未捕获，因此模板仍不可直接启用。输入 OTP 即建号、多个 OTP、验证链接或其他不同分支，可能需要调整状态机和当前动作确认。

若存在新密码创建流程，用户必须在本地完成输入、确认、提交全过程；驱动只等待 `accountSuccess` 并用 `accountIdentity` 核对参与者邮箱。密码分支不能通过自动点击最终账号提交来补足人工步骤。

### 实际抽签表单、国家区号与短信

`eventUrl` 是活动说明地址，不是已经验收的报名入口。报名开放后还需核对真正的表单地址、必填资料、是否需要账号、区号选项和成功／错误标记。美国 +1 是否受理以及 DuoPlus 是否收到 Cityline 短信，不能由格式校验或示例下拉框推断。

账号阶段可独立准备。若账号已经完成而抽签配置缺失，驱动停在 `blocked / configuration_required`；原浏览器会话仍在时，补全并核实抽签配置后，可对同一个任务再次 start，只进入抽签阶段。若进程重启或会话丢失，则保守进入人工恢复，不重新建号。

### 页面资源与其他结构

默认浏览器路由接收规则为 Cityline HTTPS。`allowTurnstileResources` 默认为 false；经核实并明确开启后，对实际进入拦截器的初始可见请求，才为当前 Cityline 页面下的组件脚本、子 iframe 及内部资源请求最小放行精确来源 `https://challenges.cloudflare.com`。未知 frame 上下文或不匹配来源的可见请求被拒绝，主框架／新窗口另有 Cityline 范围核对与导航观察；保留阻止 Service Worker 和关闭可观察 WebSocket 的设置。

这属于浏览器拦截层能力，不是网络防火墙。Playwright 官方说明重定向时路由可能只接收到首 URL；页面导航提交后的观察和关闭不能证明每跳请求发出前均已隔离。默认 Cityline 规则和 Cloudflare 最小放行都受这一限制。[Playwright 路由说明](https://playwright.dev/dotnet/docs/api/class-page#page-route)

该开关不改写 CSP、响应头或浏览器安全设置，不处理验证 token，不代理或替换挑战脚本，也不代做人机验证。Cloudflare 的官方文档支持脚本／iframe 来源及原始脚本加载这一资源需求；它不证明当前 Cityline 的组件或端到端流程已通过。[CSP 参考](https://developers.cloudflare.com/turnstile/reference/content-security-policy/)、[客户端渲染](https://developers.cloudflare.com/turnstile/get-started/client-side-rendering/)

若还存在其他必要的第三方认证、CDN 或 CAPTCHA 依赖，仍需单独核实和专门适配，不能直接放开所有域名。导航栏的普通开窗、弹窗内发 OTP 以及可能创建账号的验证动作，也必须分别核实，不能因界面文案相似而混用配置。

当前选择器针对主页面，没有通用 iframe 路径或认证新窗口切换能力。`accountEmailIdentity` 解决可见静态邮箱身份的提交核对，不代表所有静态文本都可当作输入字段。验证码错误分支、号码格式化、多 OTP 和邮箱链接仍应按实际页面适配，不自动重试结果不明的动作。

## 验收依据

源码发布、MCP 已配置、客户端发现工具、用户手工完成账号、真实页面适配完成、程序真实登记完成，应分别陈述。真实单人流程验收至少需要：

1. 客户端实际调用到同一个本机任务服务。
2. 真实入口、阶段字段、OTP／建号动作后果与结果标记已核实，且必要资源正常加载。
3. 该参与者的区号和接码能力通过实际流程核验。
4. 程序执行正常步骤，用户完成应由本人操作的密码、图形验证、条款及每次当前动作确认，并核对提交结果。
5. 收到官方登记确认邮件。若编号由用户提供，继续保留 `user_reported`，不表述为独立邮件核验。

当前仍应按开发预览描述。人工账号成功与离线回归通过，不会自动完成真实抽签流程的验收。
